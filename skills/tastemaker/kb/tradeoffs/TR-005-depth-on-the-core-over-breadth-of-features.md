# Depth on the Core Interaction over Breadth of Features

## Ranking

**Spend craft on the one interaction the product exists for until it feels inevitable, before spending it on additional features, even when each additional feature is cheap to build.**

## Why

Every product has a core interaction: the thing a user does most, or the thing they came for. Its quality sets the user's sense of the whole product. A second feature at 80 percent polish adds less than the core moved from 90 to 99, because the core is touched every session and the feature is touched occasionally.

Breadth is seductive because it is visible on a roadmap and easy to count. Depth is invisible until it is missing. When AI tools make each additional feature cheap, the pull toward breadth gets stronger and this ranking matters more. The scarce resource is no longer the ability to build. It is attention, coherence and the care to finish one thing completely.

The cost accepted is a shorter feature list and lost deals with users who wanted the missing breadth. A product that holds this ranking will be called limited by the users it turned away. That is the trade, made on purpose.

## How to Spot the Conflict

- A roadmap or scope list adds features while the core interaction still has rough edges, missing states or unfinished motion.
- The product cannot be described by a single verb.
- Polish is spread evenly across many surfaces, so no surface feels finished.
- In scope mode: items classified as competing with the core, and items that sit beside it, both draw on craft budget the core still needs.

Cite TR-005, name the core interaction, and defer the items that sit beside it.

## Exemplars

**Consumer platform (early touch phones).** The first generation of multitouch phones shipped without features competitors had, and spent its craft on scrolling, inertia and direct manipulation. The core interaction defined the category.

**Developer-tool craft (speed as the feature).** Issue trackers that compete on speed and keyboard flow invest in latency and the feel of one action over adding new modules.

**Hardware and instruments (focused devices).** Single-purpose instruments and synthesizers ship a narrow feature set with deep, tactile control over it. The constraint is the identity.

## When It Flips

- **Platforms and suites:** when breadth is the value (an all-in-one admin console, an integration platform), the core interaction is coverage itself, and missing breadth blocks the job.
- **The core is done:** when the core interaction is genuinely finished and verified, breadth is the next lever. The ranking is about order, not prohibition.
- **Table stakes:** a missing capability that users require to adopt at all (export, sign-in, accessibility) is a floor, not breadth.
